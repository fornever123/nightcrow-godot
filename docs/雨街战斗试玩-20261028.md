### 6. 问题清单

**§3.4 里没验证的项**
1. 真人通关时长：没有真人数据。机器人打完一轮 5.4～6 分钟（含 4～5 次死亡重来），和 5 分钟目标接近；但 7 局里 3 局卡在廊桥段打不完（见 §5）。
2. 难度：机器人的近战受击里甲影占 40%～60%，死亡也集中在有甲影的第二、三处。甲影伤害 15、打不浮空、只能站着磨 220 血，难度主要来自它 + 堆数量，不是来自读招。
3. 手柄：**完全不支持**。`player_factory.register_input()` 会把每个动作的输入先清空、只绑键盘；暂停菜单认手柄，游戏本身不认。
4. 性能：1080p 128 fps，没问题（只测了这台机器）。
5. 高处弓手驻守不射：**代码里确认会发生**。影弓优先刷在最高的出生点（钟楼屋顶 −260、河岸屋顶 −260），而它只在高差 < 300 时才开弓，瞄准又限 ±26°；玩家在街面（580）时它既不射也不下来（只有玩家水平距离 < 344 才往下追）。结果就是“一只看不见的弓手站在屋顶，波次结束不了”，玩家只能自己找上去。

**我看到的手感和敌人问题**
6. 敌人没有个性：四类共用一套“走近 → 前摇 → 一刀 → 后摇”，近战两类只差数值；每类只有一种攻击，没有连招、没有不同节奏、没有需要不同应对的招。
7. 防守靠掷骰子：玩家一出招，影卒 20% / 甲影 35% 概率瞬间举刀挡、影卒 15% / 影弓 40% 瞬间翻滚（带无敌）。玩家事先看不出来，体感是“随机被挡、随机打空”，越连越憋。
8. 失衡系统关掉后，“弹刀 → 破防 → 挑飞”这条最爽的链断了：弹刀只换来 34～40 帧硬直；甲影整场只能站着磨 220 血。
9. 读招太快太同质：影卒 0.3 秒出伤，三种提示颜色都是橙色；屏幕外的敌人照样出刀 / 放箭，屏外箭头只指位置不预警；炸弹飞行时不标落点。
10. 看不清敌人：实机里影卒是深蓝黑剪影，压在深蓝的雨夜背景上，主要靠黄眼睛和头顶小血条认；三只挤在一起时主角也被吞掉（见录像 33～46 秒）。外观以后换“晨使”，但现在的轮廓光 / 描边强度也影响读招。
11. 蓄力斩太拖：212 帧里有 139 帧后摇，只能跳取消，放一次等于 2 秒站桩。
12. 死亡千篇一律：四类都是同一套飞出去 + 淡出；没有“最后一刀”的定格和分量（只有每波最后一只有 0.45 秒慢动作）。
13. 底部常驻两行操作说明 + 屏幕中间的教学提示，在战斗里很挤（UI 线的事，转告）。
14. 站着不动挨打时日志里出现过 `Invalid polygon data, triangulation failed`（没定位，可能是敌人或特效画多边形）。

### 7. 改进方案（按收益排序）

只谈行为和手感；外观等“晨使”替换。凡是需要新动作帧的地方都标出来，那部分要用户出素材。

| # | 做什么 | 收益 | 成本 | 要新素材吗 |
|---|---|---|---|---|
| 1 | **修卡关的高处弓手 / 跨层待命 + 屏外预警**：弓手只刷在能射到街面的高度（≤ 一层楼）；玩家在别的层超过 3 秒，弓手换位（跳下 / 走到楼边）或改放抛射箭；近战敌人上不去时绕路找楼梯 / 平台，或干脆退到玩家下方等着、给玩家一个“下来打”的提示；先真人走一遍廊桥段 x≈11985 看主角会不会卡；屏外敌人进入前摇时，屏幕边的箭头变成闪烁的预警；炸弹飞行中就在地上标落点 | 消掉流程最大的坑；读招从“看到了才知道”变成“提前知道” | 小 | 不要 |

## 2026-11-02 战斗线：刀气（近战判定）是怎么算的 + 「打着打着打不到」修复

### 刀气 / 近战判定的机制（回答用户「空中移动的时候刀气怎么判定的，是刀气期间刀气覆盖的所有范围吗」）

**不是扫掠范围，是逐帧采样。** 结论先说：

- 判定盒是玩家身上一个跟随的 `Area2D`（`player.tscn` 的 `MeleeHitbox`，layer 8 / mask 4），
  每招出手时按 `battle.json` 的 `hitbox` 改写它的位置和大小（`player.gd` `_start_move`），
  朝向翻转时按 `_melee_base_offset_x * facing` 贴到身前（`_sync_melee_offset`）。
- 只在招式的 **active 阶段** 才查：`_process_attack` 里 `phase == &"active"` 时调 `_do_hit_check()`，
  里面就一句 `_melee.get_overlapping_areas()` —— 拿**这一帧**和判定盒重叠的敌人 Hurtbox。
  帧与帧之间不补扫、不记录「上一帧的刀在哪里」，所以**没有「刀气覆盖过的整条弧」这个概念**，
  只有「active 的这 N 帧，每帧一个矩形，矩形和 Hurtbox 相交就算到」。
- 所以「看起来刀划过去了却没中」的两种情况：
  1. 敌人是在**判定段结束之后**才进到盒子里（视觉上刀还在挥，但 active 已经过了）；
  2. 敌人**一帧之内从盒子的这一头跳到另一头**（盒子 190～250 px 宽，60 fps 下要 ~10000 px/s 才可能穿过去，
     平时只有被弹刀炸飞、连锁撞人这种速度才会）。
- 同一刀对同一个敌人**只算一次**：`_hit_this_swing` 用实例 id 记账，`_start_move` 时清空；
  所以一刀里对面挤了三只就同时中三只，但同一只不会吃两下。
- 判定还要过几道闸：必须在身前（`signf(dx) != facing` 的会被丢掉，这就是「背后的怪打不到」）、
  活着、有 `take_hit`；进到 `shade.take_hit` 里，**翻滚无敌帧**和**举刀格挡**都返回 true（= 这一刀落空 / 被挡）。
- **顿帧不会吞判定帧**：`hitstop_frames > 0` 时 `_physics_process` 直接 return，`move_frame` 不前进，
  所以 active 帧是「冻结」而不是「被跳过」。
- 空中和地面用的是**同一套**：它跟着玩家节点走，人怎么移动盒子就怎么移动；空中出刀只是把盒子
  下沿延长（见下）。

## 2026-11-03 追加：空中招互相抢招（打断 / 被打断）

用户：「空中冲刺斩应该能打断和被打断任何招式，空中攻击同理。空中攻击第三刀后摇降低」。

### 规则

| 场景 | 结果 |
|---|---|
| 在空中出任何招 → 双击方向（空中冲刺斩） | **立刻切招**，不看前摇/判定/后摇，也不等接招窗口 |
| 空中冲刺斩进行中 → 按 J / W+J / S+J | **立刻被切掉** |
| 空中攻击进行中 → 双击方向（空中冲刺斩） | **立刻被切掉** |
| **空中攻击 × 空中攻击**（第 1 刀时再按 J） | **不抢招**，仍走正常接招窗口（用户 11-03 补充：“空中攻击应该是能打断空中攻击以外的”） |
| 空中连段进行中 → 按 K 远射 / 弹刀 / 蓄力 | **不打断**（10-xx 的「K 不冻结、不回退空中连段」继续有效） |
| 地面上出招 → 按冲刺斩 | **不打断**（抢招只在空中） |
| 空中的冲刺斩次数 | **无限**（`airCombat.airDashUnlimited`，默认开；关掉回到每次腾空 1 次） |

### 实现

`player.gd` 的 `_process_attack` 最前面加一条 `_try_air_interrupt(mv, frame)`：

```gdscript
if _try_air_interrupt(mv, frame):
    return
```

它只看两件事：人在空中、`_resolve_attack_command()` 给出的指令是不是「空中冲刺斩 / 空中三连 / 空中上挑 / 下落攻击」。
是就直接 `_begin_command()` 切招 —— 这是"抢招"，不是"接招"，所以故意**不**复用 `link_open` 那套（那套要等前摇/判定过去）。

**为什么把 K / 弹刀 / 蓄力排除在外**：它们抢招会把 10-xx 定的「K 不冻结、不回退空中连段」废掉，
`action_flow` 里正好有一条测这个；实装时先放进去过、被测试逮住，才收窄成"只有空中招能抢"。

### 空中第三刀后摇

`air_light_3` 的 `recoverySpeed` 4.6 → 7.9、`tailSpeed` 3.4 → 5.8：后摇 **12 → 8 帧**，整招 18 → 14。

```

空中第 1 刀 → 再按 J   → 仍是 air_light_1              （空中攻击不抢空中攻击）
地面普攻 light_1 → 冲刺斩 → light_1                   （地面不给抢招）
空中第三刀：后摇 8 帧 / 整招 14 帧
```

### 空中冲刺斩无限用

`player.air_dash_unlimited`（默认 true，数据在 `battle.json` 的 `airCombat.airDashUnlimited`）：

- 打开：`_dash_allowed()` 在空中有求必应，出招也不扣 `_air_dash_left`。
