## 1. 实际序列帧评估（已检查原图）

| 项目 | 实测结果 |
|---|---|
| 动作 | 4 组，全部是空中动作：下坠 8 帧、空中普攻一段 8 帧、二段 9 帧、三段 19 帧，共 44 帧 |
| 尺寸 | 每帧 3200×3200 透明画布，角色本体约 1000 px 高，四周大面积空白 |
| 画法 | 高清 Q 版赛璐璐：约 3.5 头身、粗深色描边、两到三阶硬阴影、平滑抗锯齿边缘。单帧约 17 万种颜色，不是像素画 |
| 与参考图 | 发色渐变、白色挑染、护甲、剑、配色都一致，可以视为同一角色 |
| 帧节奏 | 几乎每两帧是同一姿势（相邻帧平均差异 0.49/255），相当于「一拍二」。四组实际姿势数约为 4 / 5 / 5 / 10 |
| 刀光 | 刀光直接画在角色帧里，和角色同为紫色 |
| 缩小测试 | 缩到 150～260 px 高，粗描边和白色护甲仍能看清轮廓；深色衣服在深色背景上会和背景融在一起 |
| 瑕疵 | 部分刀光边缘有 AI 放大造成的模糊和涂抹；不同动作的角色在画布中位置不同 |

### 结论
1. 【建议】画风定为「高清 Q 版赛璐璐 2D」，不做像素风。改像素风等于把现有素材全部重做，没有收益。
2. 【建议】「一拍二」对动作游戏是优点。它接近手绘关键帧，起手、出刀、收招都清楚。以后的动作也按这个节奏生成。
3. 【建议】刀光和角色分层。现在刀光画在角色帧里，导致三个问题：不能单独调颜色或亮度；命中停顿时刀光跟着停；刀光遮住角色。已有的四组可以先用；新动作尽量要求「无特效」版本，刀光另外生成或在程序里绘制。
4. 【建议】导入前必须处理。3200×3200 的原图一帧约 40 MB 显存，44 帧约 1.8 GB。导入流程：裁掉空白 → 统一角色缩放 → 统一脚底或重心锚点 → 缩到显示尺寸的 2 倍 → 打包图集。处理后单帧约 1 MB 以内。原图保留不动。
5. 【建议】显示尺寸：1920×1080 下角色约 180～220 px 高。缩小用高质量重采样预处理，游戏内开 mipmap 或线性过滤，不要用 nearest（那是像素画的显示方式）。

## 2. 核心乐趣

【建议】一句话：**把敌人挑上天，在空中连砍，再决定最后把它砸向哪里。**

乐趣分三段，每段对应一个玩家决策：

1. **挑起**（地面 → 空中）：找到破绽，把敌人挑飞。决策是「什么时候出手」。
2. **空中连段**（空中停留）：在空中维持连击。决策是「继续连，还是收尾」。连得越久，收尾越强，被打断的风险也越大。
3. **终结方向**（空中 → 落点）：用最后一击决定把敌人打向哪里：砸地、撞墙、撞其他敌人、打进场景机关。决策是「打到哪里收益最大」。

第三段是本作区别于普通动作游戏的地方。浮空连段在《鬼泣》《DNF》里很常见，但它们的连段终点多半只是「敌人掉下来」。本作让终结方向有意义，空中连段就有了目的。

正式素材正好全是空中动作（下坠、空中三段普攻），说明你自己的直觉也偏向空战。规划顺着这个方向走。

### 战斗机制建议

| 机制 | 作用 | 备注 |
|---|---|---|
| 挑飞 | 进入空战的入口 | 地面上挑、蓄力挑飞、弹刀后反击挑飞 |
| 空中三段普攻 | 维持浮空 | 已有正式素材。每次命中给敌人一点向上的速度，让角色和敌人一起留在空中 |
| 浮空衰减 | 防止无限连 | 同一次浮空中，每多一击，敌人上升量递减、下落加快。到一定段数后必须收尾 |
| 空中终结技 | 决定方向 | 下砸、横斩、上挑三种方向，用方向键选择 |
| 撞击伤害 | 奖励选对方向 | 撞墙、撞地、撞其他敌人、撞机关造成额外伤害 |
| 连锁击飞 | 群战爽点 | 被打飞的敌人撞到其他敌人，后者也被打飞。PVE 清怪的主要手段 |
| 弹刀 | 防守与反击 | 保留现有设计 |

## 3. PVE 与本地 PVP 的关系，以及设计冲突

### 关系
【建议】共用同一套战斗系统，用不同的规则层。

- **PVE**：敌人数量多，体重不同；重点是空中连段的长度和终结方向。胜负看清场。
- **本地 PVP**：1v1 或 2v2；同一套招式，但打开「反制」规则（受身、空中脱离）。胜负看击飞出界或血量。

### 主要冲突（必须提前处理）

| 冲突 | 原因 | 解决办法（建议） |
|---|---|---|
| 浮空连段 vs PVP | PVE 里长连段是爽点；PVP 里被连 10 秒没有操作，就是折磨 | PVP 打开「空中脱离」：被连到一定次数或伤害后，可以按键挣脱，消耗资源。PVE 敌人不使用或只有精英使用 |
| 击飞出界 vs PVE 爽感 | 敌人一出界就消失，玩家没办法继续空中连段 | PVE 场地以封闭竞技场为主，墙壁反弹，靠撞击造成伤害；只有少数场景有深渊或尖刺作为奖励点 |
| 长连段 vs 平衡 | 同一套数值，PVE 想要更长，PVP 想要更短 | 浮空衰减、受身、硬直等参数分成 PVE 和 PVP 两套，存在 battle.json 的不同配置里 |
| 单角色 vs PVP | PVP 只有夜鸦对夜鸦，深度不够 | 第一阶段用镜像对局验证；以后加第二名角色。PVP 定位是「辅」，不要求一开始就有大量角色 |
| 镜头 | 空中连段需要镜头跟随，同屏 PVP 需要镜头同时框住两人 | 动态镜头：按所有角色的范围自动缩放，设上下限 |

### 同机对战 vs 局域网联机（不替你选，只说明区别）

| 项目 | 同机对战（一台电脑，多手柄） | 局域网联机（多台电脑） |
|---|---|---|
| 网络代码 | 不需要 | 需要。格斗/动作游戏对延迟敏感，至少要做状态同步；想要手感好需要回滚网络代码 |
| 开发量 | 小：多个输入设备 + 共享镜头 | 大：同步、断线、匹配、房间、不同步排查。工作量可能超过整个 PVP 模式本身 |
| 镜头 | 必须同屏，镜头要框住所有人 | 每人可以有自己的镜头 |
| 对现在架构的要求 | 输入和角色分开即可 | 战斗逻辑必须固定帧率、结果只取决于输入，否则以后改不动 |
| 测试 | 一个人加两个手柄就能测 | 需要两台电脑 |
| 适合 | 朋友一起玩、Demo、展会试玩 | 朋友不在同一台电脑前 |

我的倾向（供参考，不代表已选）：先做同机对战；架构从第一天起按「固定帧率、结果只取决于输入」来写。这样以后要不要做局域网，可以随时决定，不用推倒重写。

## 4. 击飞值表现与血条

### 击飞值：翅膀 vs 屏幕 UI
看过实际画面后，我同意你的判断：只靠翅膀不行。
- 1080p 下角色约 200 px 高，背后的小翅膀只有约 30～40 px，战斗中还会被刀光和身体挡住。
- 翅膀是深紫色，和刀光、头发颜色接近，变化看不出来。
- 敌人没有翅膀，这个办法不能通用。

【建议】主信息用屏幕 UI，角色身上只做辅助：
- **主信息**：屏幕角落的角色头像框 + 数值或环形槽（类似大乱斗的百分比）。数值越高，颜色越暖（白 → 黄 → 橙 → 红）。
- **辅助**：危险时角色身上掉黑紫羽毛、轮廓闪红边。这样眼睛不用离开战场也能感觉到危险。
- **敌人**：小怪不显示数值，只在头顶出现简短的状态（如浮空计数）；精英和 Boss 在屏幕上方显示。

### 是否需要血条
这取决于「击飞值」到底是什么。两种做法：

| 方案 | 规则 | 优点 | 缺点 |
|---|---|---|---|
| A. 只有击飞值，没有血条 | 击飞值越高，飞得越远；打出界、撞死才算击杀 | 规则统一，PVP 和大乱斗一样直观 | PVE 封闭场地里很难「打出界」，杀敌方式受限 |
| B. 血条 + 击飞值 | 血条决定死亡；击飞值决定飞多远和撞击伤害 | PVE 自然；撞墙、连锁能直接扣血，爽感清楚 | 两个数值，玩家需要多理解一层 |
| C. 混合 | PVE 用 B；PVP 用 A（残机制） | 各自取最适合的规则 | 两套规则，平衡和教学成本都更高 |

【建议】PVE 用 B，PVP 先试 A 和 B 两种做原型，再决定。理由是 PVE 为主，场地以封闭竞技场为主，血条更合适。PVP 的选择要靠实际试玩来定。

## 5. 统一视觉方向

【建议】风格名：**「夜鸦哥特 · 高清 Q 版赛璐璐」**。以角色序列帧为标准，其他内容向它对齐。

| 内容 | 规范 |
|---|---|
| 角色 | 约 3.5 头身；粗深色描边；2～3 阶硬阴影；动作一拍二。敌人和第二角色沿用同样的描边粗细、头身比和阴影阶数 |
| 配色 | 主角：黑、紫、白。敌人：暖色或其他对比色（锈红、骨白、暗金），避免与主角混在一起。背景：中间调、偏冷、饱和度比角色低 |
| 背景 | 2D 手绘、分层视差（远景 / 中景 / 可站立层 / 前景）。可站立层要有清楚的边缘和描边。背景不加粗描边，细节和对比度都低于角色，避免抢视线 |
| 场景主题 | 哥特钟楼、鸦巢、月夜城墙、废弃教堂等。结构上：带墙壁的封闭竞技场 + 少量平台 + 可互动机关 |
| UI | 与角色同一套语言：粗描边、硬阴影、黑紫白配色、羽毛和十字装饰。字体清楚、粗细统一。HUD 只放头像、血条/击飞值、连击数 |
| 战斗特效 | 刀光、命中、撞击都和角色分层。主角刀光为紫白色；命中闪光用白色和高亮黄；撞击用暖色冲击波。特效保持赛璐璐硬边，不要写实粒子 |
| 可读性 | 角色加一圈浅色外轮廓或亮边（shader 实现），确保深色衣服在任何背景上都能看清 |

### 需要检查的风险
- AI 生成的不同动作，角色比例、头身比和颜色可能不一致。每批动作都要和参考图比对。
- 已有四组序列帧里刀光边缘有模糊。缩小到游戏尺寸后影响不大，但要实机检查。

## 6. AI 生成的可行性

### 可以靠 AI 做的
- 背景、UI 底图和图标、场景道具、头像、宣传图：静态图片，可行度高。
- 角色动作：现有空中三段说明可以做到。但这是成本最高、风险最高的部分。

### 主要风险和对策

| 风险 | 对策（建议） |
|---|---|
| 不同动作间角色走样 | 固定参考图（三视图）+ 固定提示词模板；每段动作完成后和参考图对比，不合格就重做 |
| 动作时间不可控（出刀帧位置、收招长度） | 生成后由修改器标注起手、生效、收招帧；不合适就删帧或重复帧调整节奏 |
| 刀光和角色粘在一起 | 新动作要求生成无特效版本；刀光单独生成或程序绘制 |
| 敌人数量多，成本高 | 敌人数量少而精：3～4 种小怪 + 2 个 Boss；用换色、改体型变出精英 |
| 风格漂移 | 写一份「风格标准表」：参考图 + 允许和禁止的元素 + 合格示例。每次生成都对照 |

### 动作需求清单（夜鸦，优先级排序）
1. 必要：待机、跑、跳起、下坠（已有）、落地、地面三段、上挑、空中三段（已有）、空中下砸、受击、被击飞、倒地、起身、弹刀。
2. 重要：冲刺 / 闪避、蓄力、空中受身。
3. 之后：远程技、终结技、胜利姿势。

每条动作建议 8～20 帧（一拍二）。必要动作约 14 组，约 200 帧。

## 7. 后续开发重点（按顺序）

| 阶段 | 内容 | 通过标准 |
