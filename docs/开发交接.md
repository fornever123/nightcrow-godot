## 结构与数据

- `project.godot` → `scenes/training.tscn` → `scripts/training.gd`。
- 唯一战斗配置：`assets/data/battle.json`。编辑器和游戏都读它。禁止再建立另一套 `.tres` 调参源。
- `assets/data/editor-project.json` 只保存编辑器工作区。
- `scripts/core/configuration.gd` 将 JSON 转为 C 盘兼容的 MoveDefinition，依据动作 FPS 和帧窗口计算 60 Hz 物理帧。
- `scripts/gameplay/player.gd`、`dummy.gd`、`projectile.gd` 保留 C 盘机制。命中停顿只冻结各自计数，不改全局 Engine.time_scale；输入先采样后停顿。
- `scripts/presentation/character_view.gd` 直接按 move_frame / 60 × animation_fps 选择动作图片。角色默认 168 高，脚底坐标与 sprite pivot 保持 E 盘约定。
- `art_cache.gd` 用 FileAccess 字节和 Image.load_png_from_buffer 建纹理，支持新导入图片无需打开 Godot 重新导入。支持图集 region，首次加载后缓存。
- `trail_view.gd` 使用 E 盘原刀光腐蚀序列，出刀阶段按角色源动作帧定位，收尾按 erosionSpeed 播放，不做整张图同时透明消失。
- `tools/battle-editor` 是 E 盘 Vue/Pixi 修改器的整合版本，新增逐帧动作工坊和战斗总表。画笔、擦除、裁剪和调色仍在 AssetsPanel。
- 本地服务默认只监听 127.0.0.1:4329，直接 spawn 项目附带 Godot。游戏用 `.runtime/game.json` 报告状态；停止通过进程专属 request 文件，由游戏自己退出。
- 游戏每 0.5 秒检查配置变更并重置场景。可在修改器关闭自动应用。启动脚本复用服务，前端仅在源码变更时构建。

## 时序约定

JSON 的 activeFrameStart、activeFrameEnd 是从 0 开始的源动作帧；end 包含这一帧。chainFrame 为开始接招的位置。修改器显示从第 1 帧开始。

syncAnimation 开启时 duration / activeStart / activeEnd / chainOpen 由帧窗口推导，不要只改秒数。动作速度和命中窗口必须一起变化。角色帧率、招式速度与命中停顿是三个独立参数。

保持原有 E 盘角色和刀光素材；不得自动生图或覆盖原刀光样板。未完成美术使用现有动作或简单图形，并在操作说明里明说。不要引入 Maker SDK、MCP、运行入口、自动加载项。
