# 桌面手调动作 · 游戏操作说明

本次使用2026-10-18桌面“实际应用到游戏的序列帧”中的24组、734张原版图片。原图完整归档，游戏使用另外生成的副本，未做3px处理。

## 打开和操作

双击工程根目录 `OPEN_GAME.bat` 打开游戏；`OPEN_MODIFIER.bat` 打开修改器。

| 操作 | 游戏表现 |
|---|---|
| A/D 或左右方向键 | 跑动；反方向时先转身再反向跑 |
| 空格/W | 起跳；空中可再跳一次；下降和实际落地分别播放对应动作 |
| 地面点J | 第一刀；在接招窗口再按J进入第二、第三刀 |
| 空中点J | 空中第一刀；再按两次接第二、第三刀；不按就停止接刀并正常落下 |
| 长按J | 沿用蓄力；松开或蓄满释放强化挑飞 |
| W+J | 地面挑飞 |
| Shift+J | 朝当前输入方向冲刺攻击；没有方向输入时沿当前朝向 |
| K | 既有远射 |
| L点按 | 短精准弹刀窗口，成功才播放弹刀反馈 |
| L持续按住 | 持续格挡；精准窗口结束后仍可普通挡住正面来袭 |
| F2 | 开关木桩测试来袭，橙色提示后会在近距离打来，可练格挡/弹刀 |
| R | 重置角色、木桩和统计 |
| F1 | 查看判定范围 |

空闲一段时间会播放收刀并保留收刀姿势，移动/攻击可结束空闲姿态。起始拔刀不会强制阻止玩家操作。测试来袭默认关闭，场景仍只有角色和木桩。

## 原版帧在哪里

- 完整原版：`art/game-ready-sequences/desktop-actions-20261018/`。24个动作目录、734张完整PNG及22份原JSON，原文件名和像素保留；`manifest.json`记录SHA256与来源。
- 游戏无损裁透明副本：`assets/image/desktop-actions/`。有1帧本来完全透明，用空帧记录保留时间，因此实际PNG为733张。
- 若运行时去除远处白碎片，清理副本另存 `assets/image/desktop-actions-clean/`；完整原版和无损裁透明副本不变。
- `source_`开头的24段是完整原片预览。游戏招式是从原片选出的用途片段；`a2`不同版本没有被重复串成额外攻击。

## 时长和空中三段

源工程与导出JSON一致：跑步、转身4FPS；起跳和落地17FPS；其余有说明的攻击动作24FPS。GIF预览每帧60毫秒，不能代替源工程时轴。下坠没有JSON，暂按其预览的60毫秒/帧播放，后续可在修改器调整。

空中原56帧保留并拆为：第一刀1～18帧（0.750秒）、第二刀19～30帧（0.500秒）、第三刀31～56帧（1.083秒）。接刀点单独标记，因此不必等整段后摇结束才接下一刀。空中攻击有有限的下落减速/滞空预算，落地重置，不能用K无限返还。

命中停顿会延长真实观看时长，但不会改变源动画FPS；人物动作和刀光一起暂停，按键仍能提前输入。所有新PNG已经合成刀光，游戏不会再重复添加旧刀光。

## 继续手调

修改器“动作工坊”显示中文动作、原文件夹、源帧范围、原时长和实际时长；“角色参数”可调转身、落地、防守、空连和拔收刀。“战斗参数”可调每招出刀、命中、接招窗口及冲刺位移。

手调工具继续用保留的分层源工程；桌面这批PNG已合成角色与特效，无法从单张PNG无损恢复两个独立图层。修改后通过现有FrameBaker导入入口替换片段，游戏和修改器仍共用 `assets/data/battle.json`。

## 开发重建和记录

原片归档和游戏运行资源一同提交GitHub，新电脑运行游戏不需要原桌面路径。重建配置可先运行 `tools/art/import_desktop_actions.py --source art/game-ready-sequences/desktop-actions-20261018`，再运行 `tools/art/configure_desktop_actions.py`；可选白碎片清理步骤位于两者之间。

导入审计：`docs/desktop-actions-import.json`；动作绑定与运行坐标校准：`docs/desktop-actions-bindings.json`；实际游戏截图：`docs/desktop-actions-visual/`。之前的原版素材与旧刀光工程继续保留作为历史资料。
