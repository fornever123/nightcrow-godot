## 1. 和这位用户合作的规则（最重要）

- **始终用简体中文**。
- **设计阶段只出方案，用户说“干活”才改代码。** 用户中途说过一次“干活”又立刻打断，之后没再说——当前仍是设计阶段。

- **用户说过“不要参考图”**：文字生图不附参考图。现在的做法是“编辑一张画布”，画布本身就是要被改的图，这不算参考图；但“在画布边上拼一条定调图、出图后裁掉”本质还是参考图，**要先问用户**。
- 用户不喜欢：把月亮 / 魔法阵 / 水晶 / 星星当特效元素（背景里本来的月亮可以）；全图一个颜色罩着；左右对称、像关卡编辑器的构图；写实 / 3D 感 / 照片纹理；器械感的平台（铁链、铁栈桥、交叉支撑脚手架）；画面太亮发灰；巨环画成正圆、月亮放在环中心。
- 用户要：**顶级好看**、和角色统一（不是反差）、**横向无限滚动**（否决过“每处一幅固定画”）、地图多层（为浮空连段）、主角不是天选之人但要够特殊（“七羽”刺客之一）。
- 用户倾向**像素化**（角色本来就小）。
- 检查每张图时：**真的打开图看**，合成真主角（`assets/image/ai-hd-20261020/idle/pose_001.png`，游戏里约 85 屏幕像素高），转灰度看明暗，和定调图并排比。用户很敏感，“差不多”过不了。

## 4. 当前流程（定稿）

详见 `docs/场景美术流程-GPT.md`。要点：

1. **只让 GPT 画整幅，不单独生成某一层。** 图层从整幅画里拆。
2. **构图我们定、上色 GPT 画**：先由程序按游戏坐标画彩色草图（block-in），GPT “照草图画成成品”。文字只说明每个色块是什么。——这解决了巨环、平台高度、地面线这些文字控制不住的问题（第 2 处 v1 实测：平台顶面误差 2 像素以内）。
3. **画布大部分是真像素**（天空、远景、桥面一截），草图只占 30～50%；草图带三档明暗、不画纹理。GPT 一次编辑会重画整张，所以**真像素部分由程序贴回原图**。
4. **按层画，不按世界画**（视差冲突是 v1 长卷方案的致命伤）：
   | 层 | 视差 | 内容 | 循环 |
   |---|---|---|---|
   | 天空 | 0（贴屏） | 夜空、月亮、碎巨环、青光云；另加 0.02～0.04 的云丝飘动 | 一张 |
   | 远景 | 0.1 | 远山 + 远云海，不放地标 | 2700（5 轮一循环，15 种偏移，拼对照图验收） |
   | 中景 | 0.5 | 每处一个独有地标（第 1 处小镇崖、第 2 处断渡槽、第 3 处驿塔），地标间补低反差小石岛 | 2700，和一轮同步 |
   | 可玩层 | 1.0 | 桥面、立面、平台 | 5400 = 3 张 1280 英雄画面 + 3 段 520 过渡 |
   | 前景 | 1.4 | 剪影零件，挂在每段数据上；英雄画面里手摆 | — |
5. **每处回潮区一张“英雄画面”**（锁镜头时看到的那一屏）；各层偏移设成“锁镜头时合成 = 英雄画面”，三处都能对上（数学已验证）。第 1 处 = 实战定调图（×0.88 盖住一屏）。
6. **拆层**：前层 = 原像素 + 程序蒙版（画草图时同时导出“物件 ID 图”）；被挡的后层 = 先程序把物件涂成模糊块，再让 GPT“把模糊区画完”。辉光、雾、倒影不抠，在引擎里做。
7. **美在引擎收尾**：2 像素格（SubViewport 640×360 最近邻，界面高清）、按定调图校色、层间雾、战斗带背光、主角轮廓光、水洼倒影、巨环光纹呼吸、鸦群、云丝。
8. **先做垂直切片**（不碰 `night_trial.gd` 的最小版）：只用定调图在游戏里做出拆层、像素格、雾、背光、倒影、光纹，和定调图并排比；满意再量产。引擎评审估计约 7 人日，步骤见 `docs/场景美术流程-GPT.md` 第 8 节。

### 定调图为什么好看（每张图的验收标准）
- 明暗三段：天空暗（亮度 20～45 / 255）、中段云海亮（60～85，峰值 >140）、桥立面和前景暗（5～35）；战斗带落在亮的中段。
- 一条光路：月亮 + 巨环 → 环下青光云 → 桥面水洼倒影。
- 色彩 90/5/5：九成靛蓝 + 中性灰，青光、暖窗各不到 3%，不挨着，**没有紫**（紫只给主角）。
- 三块不对称：左重、中空、右重；斜线指向中右的战斗区。
- 约 7 层纵深，越远越亮越蓝越低反差；云海顶线起伏。
- 平台都是同一座桥的遗骸；桥面露出约 9% 画高的顶面，像舞台地板、当镜子。

## 6. 子智能体评审的关键事实（别再踩）

- GPT 编辑**每次都重画整张图**；“保持某部分不变”像素级做不到 → 程序贴回原像素。遮罩“完全基于提示”，不一定按形状来。
- 多次编辑会**漂移**（越改越暖、越饱和、越“干净”）；每次抽 2～3 张选 1 张，失败回原画布重抽，不在坏图上连改。
- 实际出图约 157 万像素（1672×941 / 1916×821）；2 像素格下够用。
- **用 GPT 编辑拆层不可靠**（错位、洋红边、辉光丢失，成功率约 30%）；洋红底抠带辉光的东西抠不干净。
- 文字精确控制形状 / 位置不稳定；**草图控制很稳**（第 2 处 v1：输出与画布零偏移，平台顶面误差 ≤2 像素）。
- 草图是“构图”不是“工程图”：GPT 会忠实照着草图的剪影画——**剪影丑，成品就丑**（第 2 处 v1 的渡槽就是例子）。
- 天空视差 0 是对的（底板不动，加云丝制造相对运动）；底板给 0.01～0.02 会让英雄画面对不上。

## 7. 第 2 处回潮区（C 渡槽来水）：v1 检查结果与下一步

### 7.1 v1 检查（`arena2_C_gpt_v1.webp`）
- **成立**：输出与画布同尺寸、零偏移；天空和左下桥面真像素几乎没变（亮度平均差 5.5 / 6.8）；平台顶面一层 616（要 614）、二层 472（要 470）、桥面远边 712（要 714）——**碰撞可以直接按草图数据**。左上崖画得好；湿石板桥面和左边真像素接得上；平台顶的积水青光好看；三个主角都清楚。
- **不如定调图的地方**（对比图 `arena2_C_gpt_v1_vs_keyart.png`）：
  1. **远山是一条锐利、重复的亮锯齿带**（这是我放进画布的真像素，处理得不够），横穿战斗带背后，像贴纸。
  2. **断渡槽像几根平板加细棍**：草图只给了平板和细柱，GPT 照着画，没有拱、没有体量。定调图里的渡槽是连拱。
  3. **天空右上有一条竖向接缝**（x≈940，从顶到 y≈300），来自天空层合成（`make_sky_ring.py` 里那块“保住环顶”的矩形）。
  4. **光路弱**：瀑布太细太短，青光没有形成“环 → 瀑布 → 水洼”的明显一条。
  5. **没有暖色点缀**：全冷，比定调图少了生气（定调图有小镇暖窗）。
  6. **右下前景没画**：还是平涂黑块 + 几根直线。

通用做法：
- 坐标换算：游戏屏幕像素 × 1.30625 = 画布像素（1672×941）；定调图像素 × 0.88 = 游戏屏幕像素（定调图 × 1.149 = 画布）。定调图的站立线在第 659 行。
- 洋红抠图：alpha 按 `min(R,B) − G` 估计，再把边缘混进的洋红减掉（见 `key_layers.py`）；黑底云：亮度当 alpha。
- 检查：合成主角（98 屏幕像素高，含剑和头发）+ 冷色轮廓光；转灰度看五档明度；和定调图上下并排。
