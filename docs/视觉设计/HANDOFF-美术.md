## 4. 硬约束（来自实测，写提示词必须遵守）

可读性测试：`docs/视觉设计/art/bg-value-hue-test-small.png`。

1. **背景禁用紫色和高饱和蓝紫色。** 紫背景在任何明度下都会吃掉角色的紫发和紫刀光。月夜场景的靛蓝也要压低饱和度。
2. **背景主体明度 28%–60%。** 太暗角色的黑衣服会融进去；太亮失去氛围。
3. **青灰、青绿基调最安全**，暖琥珀色只作点缀（光源、窗口、云边）。
4. **前景剪影只放在画面左右两端和最底部**，中央行走区不放任何遮挡物。（参考视频的大黑柱会把角色挡住，测试已证明）
5. **地面表面要安静**：行走线附近细节少、对比低，复杂纹理只放在地面下方的剖面里。
6. 战斗画面**中央下方约 40% 保持空旷平静**，用来放角色。
7. 文字永远不要指望模型生成，程序渲染。
8. 白色轮廓光会显得廉价，不要用。

## 7. 提示词写法（GPT / Gemini 通用）

两者是指令跟随模型，不是关键词检索。

1. **不要堆质量标签**（masterpiece、8k、trending on artstation 没用）。有用的是笔触、边缘硬度、明暗层次、材质。
2. **固定顺序写简报**：用途 → 素材类型 → 画面内容 → 风格 → 色彩限制 → 构图 → 排除项 → 平铺要求。
3. **排除项必须写，且写全**：人物、角色、怪物、文字、UI、边框、Logo、水印。不写就一定出现。
4. **必须显式要求「中央下方留空」**。
5. **用语言量化层次**：远景最暗最简，近景最亮最清楚。
6. **一致性靠参考图，不靠重复提示词。** 先出一张风格锚图，之后每层都附上它，并在开头写「参考附图的画风、笔触、色调和明度，保持完全一致」。Gemini 支持多张参考图。
7. **改图用编辑，不要重新生成**：「只修改 X，其余全部保持不变」。
8. 一次出 4 张挑。
9. 比例在工具里也要设置。若不支持 2:1，用 16:9 生成再裁切或外扩。
10. **AI 做无缝平铺经常失败**，拿到图先查左右边缘；接不上就用第 9 节的修接缝提示词。
11. 透明素材：纯洋红 `#ff00ff` 底，并写明「主体禁止使用该颜色，边缘与背景清晰分离」。发光特效用纯黑底，游戏里叠加混合，不用抠。

**修接缝**：先把图左右各切一半、交换位置（接缝会移到画面正中），再交给 Gemini 编辑。

```
只修改画面正中央的竖直接缝区域，让左右两侧的云层、岛屿、石块和光照自然连续。保持画面其余部分完全不变，不改变风格、颜色和构图。
```

**灰度明度稿**（检查明度结构）

```
把这张图以完全相同的构图重新渲染为灰度明度稿，不要任何颜色。远景最暗，中景中灰，地面表面是最亮的大块面，中央行走区域明度平静、没有杂乱细节。
```

## 10. 收到用户的图以后怎么检验

做法：把角色按目标尺寸合成进背景，缩到 1920×1080 再看，另转一份灰度。

```
角色合成要点（Pillow）：
1. 打开 44 帧序列帧中任一帧，按 alpha>8 取包围框裁掉空白
2. 缩放到目标高度（建议 260 px）
3. 轻度像素化：先缩小为 1/块 大小（LANCZOS），alpha 以 110 为阈值二值化，
   颜色量化为 48 色，再用 NEAREST 放大回原尺寸（块 = 2 或 3）
4. 底边对齐地面行走线后合成
```

现成脚本在 `docs/视觉设计/`：`ref_fit_test.py`、`battle_size_test.py`、`bg_value_test.py`。尺寸对比图的参考是 `art/gpt-size-compare.png`。
可用的工具：`python`（已装 Pillow）、`ffmpeg`、Chrome 无头截图（`C:\Program Files\Google\Chrome\Application\chrome.exe`）。

**验收清单**

- [ ] 角色（260 px 像素化版）放进去后轮廓清楚，与场景比例协调
- [ ] 角色在行走区任意位置不会被前景遮挡
- [ ] 角色脚下的地面纹理是安静的
- [ ] 背景没有饱和紫和高饱和蓝紫
- [ ] 四层左右都能无缝平铺
- [ ] 洋红底能干净抠出，边缘没有洋红残留
- [ ] 四层画风一致（笔触、明度关系、色调）
