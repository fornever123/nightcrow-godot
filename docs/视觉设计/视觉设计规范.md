## 一、主题

**主题名：钟塔围猎（Bell Tower Hunt）**
副标题：把敌人挑上天，再摔碎在钟塔上。

夜鸦在哥特钟塔的夜色里猎杀。钟塔是舞台，也是凶器：悬钟、钟绳、飞扶壁、彩窗、铁栏、深渊。战斗围绕着「把敌人打向哪里」展开。

### 为什么是这个主题（而不是随便选一个好看的夜景）

1. **它和核心玩法长在一起。** 击飞需要「可以撞的东西」。钟塔提供墙壁、钟、铁栏、深渊，全部是天然的撞击目标。换成森林或科幻走廊，就没有这套现成机关。
2. **它和角色的视觉天然一致。** 你的角色是黑紫、白挑染、羽毛、长剑。哥特钟塔的深蓝夜景、彩窗紫光、石质灰蓝，正好是同一族颜色，不用改角色。
3. **它建立了画面层次。** 夜→深蓝→灰蓝→暖光，正好形成一条从「远、暗、冷」到「近、亮、暖」的层级，方便排布可读性的优先级。
4. **它有辨识度。** 市面上多数横版动作是废墟、街道或森林；钟塔内部加悬钟机关的组合很少见，一眼能记住。

### 三条设计支柱

| 支柱 | 含义 | 落到画面上 |
|---|---|---|
| 猎杀 | 玩家是猎人，不是被打的一方 | 玩家永远是最亮、最高对比的元素；受击时画面给玩家加红边警告 |
| 击飞是武器 | 场景是凶器，不是装饰 | 机关、墙壁、深渊用暖色自发光标出，永远可见 |
| 可读第一 | 画面再美，看不清就作废 | 站立层、角色、敌人都有明确描边；特效不得遮挡角色 |

## 二、视觉语法：颜色即规则

这是整套设计里最重要的一条。玩家不需要看说明，只靠颜色就能读出信息。

| 颜色 | 归属 | 含义 |
|---|---|---|
| 黑 + 紫 + 白 | **只有玩家** | 紫色是玩家的专属色。任何不是玩家的东西都不许用紫 |
| 锈红 + 骨白 + 暗金 | **敌人** | 看到暖色就是能打的东西 |
| 亮橙 + 自发光 | **机关 / 危险区** | 尖刺、深渊、可撞钟体。永远带自发光 |
| 冷蓝紫（低饱和） | **背景** | 背景永远比角色暗、比角色灰 |
| 白 → 黄 → 橙 → 红 | **裂羽值梯度** | 同一条暖色梯度也用于「即将被击飞」的警告 |

### 取舍说明

- **取舍一：牺牲画面的柔和感，换取平台边缘的清晰。** 站立层用中亮蓝紫加亮色描边（#7C6FBF），比常见的「暗色石头」更亮。理由：横版动作游戏里，踩不到平台是最致命的体验问题。玩家不会抱怨地面太清楚。
- **取舍二：紫只给玩家。** 你的角色和刀光都是紫色，如果背景也用紫，角色就会「融进画面」。所以背景紫一律降饱和、降明度，且不用纯紫。
- **取舍三：敌人禁用紫色系。** 敌人用锈红、骨白、暗金。这样在混战时，玩家一眼就能从颜色分辨「谁是我、谁不是我」。

### 色板（直接可用的十六进制值）

| 用途 | 值 | 说明 |
|---|---|---|
| 天穹暗部 | `#0E0F22` | 最远景 |
| 钟楼中景 | `#232445` | 建筑主体 |
| 可站立层 | `#3C3866` | 平台表面 |
| 站立层描边 | `#7C6FBF` | 平台顶边，5 px |
| 角色紫 | `#6E4BD6` | 与角色素材同族 |
| 角色亮紫 | `#B792F6` | 刀光、强调 |
| 角色亮边 | `#C9B6FF` | 外轮廓光 |
| 敌人锈红 | `#C2543C` | 敌人主色 |
| 敌人骨白 | `#E3C08A` | 敌人描边／高光 |
| 机关橙 | `#FF8A3D` | 机关自发光 |
| 危险红 | `#FF3B47` | 高裂羽值、濒死 |
| UI 底板 | `#12111F` | 面板底色 |
| UI 描边 | `#5B4E9E` | 面板边线 |
| 正文 | `#EDE9F7` / `#9F98BE` | 主／次文字 |

**色盲冗余编码**：紫与橙对红绿色盲可区分，但对蓝色盲偏弱。因此裂羽值不只靠颜色，同时用「环的填充长度 + 数字」表达，危险状态另加形状变化（外环出现尖刺缺口）。不依赖颜色即可读懂。

## 三、战斗画面的可读性规则

这是「画面好看」和「打得清楚」之间必须做的工程。规则按优先级排列，冲突时上位覆盖下位。

1. **中央区域永远干净。** 1920×1080 中央 1280×620 区域内，只允许出现角色、敌人、特效、伤害数字。任何常驻 UI 不得进入。
2. **角色必须有亮边。** 角色素材本身是黑紫、深色衣服，在深蓝背景上会糊。用 shader 加一圈 2 px 亮边（`#C9B6FF`），确保任何背景上都看得见。这是最便宜、收益最大的一条。
3. **特效不得遮住角色。** 命中特效围绕角色轮廓外侧生成，不在角色身体上叠大块白光。现有素材的刀光已经画在角色帧里，这种情况要把刀光的透明度上限压到 80%，并且不做全屏泛光。
4. **命中反馈按「来源」分色**：普通命中 = 白色闪光；撞墙 / 撞地 = 暖橙冲击；连锁击飞 = 黄绿细线连接两个敌人；弹刀 = 白色十字。玩家不看文字就知道发生了什么。
5. **同时最多显示三处特效。** 超出时按优先级丢弃：撞击 > 终结 > 普通命中。
6. **背景中景的亮度上限** = 站立层亮度的 60%。任何背景元素亮过地面，就是错误。
7. **危险区必须自发光且恒定可见。** 尖刺和深渊加轻微呼吸动画，打击时更亮。
8. **受击一方加红边。** 敌人被击飞时轮廓闪暖红；玩家血量低时屏幕四周加淡红暗角。

## 四、HUD 布局规范

所有常驻元素贴边放置，锚点固定。标注图见样张 1（点右下角按钮切换标注层）。

| 元素 | 位置 | 尺寸 | 内容与规则 |
|---|---|---|---|
| 玩家头像 + 名字 | 左上，距边 48 px | 头像 112×112 | 头像用角色半身切片，切角形状 |
| 血量条 | 头像右侧 | 330×16 | 细条，白→浅紫。**刻意做细**，见下方取舍 |
| 裂羽值环 | 血量条下方 | 56×56 环 + 数字 | 主信息。环填充从 12 点方向顺时针；颜色随数值走白→黄→橙→红 |
| 关卡进度 | 顶部正中 | — | 当前层名 + 房间点阵，Boss 房用暖红长点 |
| Boss / 精英 | 右上，距边 48 px | 宽 520 | 名称 + 血条（从右向左减）+ 状态标签（如「霸体 · 需撞击破防」） |
| 连击数 | **左下**，距边 48 px | 数字 78 px | 见下方取舍 |
| 浮空计数 | 连击数旁 | 22 px | `浮空 ×3`，暖黄 |
| 招式提示 | 右下，距边 48 px | 14 px | 可关闭。只在教学关和暂停教学里默认开启 |
| 伤害数字 | 跟随敌人上方 | 56 px | 白字加深色描边；撞击伤害附来源文字（「撞墙」） |

### 取舍说明

- **取舍四：连击数字放左下，而不是正下方中央。** 中央下方是最容易遮住角色和敌人的位置。移动端和主机上的成熟做法是把它推到边角。代价是视觉冲击小一点，收益是永远不挡画面。
- **取舍五：血量条做细，裂羽值环做大。** 本作的核心信息是「谁快被打飞了」，不是「谁掉了多少血」。如果血条很粗，玩家会一直盯着血条，忽略击飞值，核心玩法就传达不出去。这是**故意让 UI 引导注意力**。如果你认为血条应该更醒目，这条可以改，但要把教学也一起改。
- **取舍六：HUD 不加装饰性边框和图案。** 斜切角 + 羽毛装饰只用在菜单和结算这类「允许慢看」的界面。战斗 HUD 保持极简，因为它每一帧都在消耗玩家的注意力。

### 界面组件规范

- **形状语言**：斜切角（对角切 16 px），呼应角色护甲和翅膀的尖角。主要按钮切左上和右下，次要面板切右上和左下。
- **羽毛装饰**：只出现在菜单标题、结算、加载页。战斗 HUD 不用。
- **字体**：中文与正文用无衬线黑体（思源黑体 / MiSans），字重分明；数字与英文标题用衬线体（如 Georgia），因为钟塔主题需要一点古典感，且衬线数字在震动画面里更容易辨认。
- **按钮**：主要按钮浅紫渐变底 + 深色字；次要按钮描边空心。
- **动效**：入场用「羽刃划过」的白痕擦除，不做缩放弹跳。时长 180–260 ms。

## 五、场景与镜头

### 分层（视差）

| 层 | 移动系数 | 内容 | 亮度上限 |
|---|---|---|---|
| 远景 | 0.10 | 夜空、月、尖顶剪影、云 | 最暗 |
| 中景 | 0.35 | 拱窗、石柱、飞扶壁、悬钟 | 站立层的 60% |
| 站立层 | 1.00 | 地面、平台、可踩物件 | 基准亮度 |
| 前景 | 1.25 | 栏杆、钟绳、飘落的羽毛 | 深色剪影，禁止用到 40% 以上不透明 |

### 竞技场规范（PVE 与 PVP 共用）

- 一个房间 = 一屏宽（1920 px 设计宽）或多半屏，高 1080 px。
- 站立层占画面下方 25%–30%，上方留出空战空间。**这一条由玩法决定**：空战需要垂直空间，所以本作镜头比一般横版动作游戏更「抬高」，能看到更多天空。
- 每个竞技场至少提供：2 处可撞墙壁、1 处可撞机关（钟、铁栏）、1 处危险区（深渊或尖刺）。
- 墙壁用亮色描边标出可撞区域。玩家要能预判「打到这里会撞」。
- 边缘用暖色自发光标出，禁止用和背景一样的冷色。

### 镜头

- 跟随玩家，带 0.12 秒左右的缓动，向上留出更多空间（因为空战）。
- 裂羽值高、浮空连段时长连击数高时，镜头轻微推近（放大到 1.08 倍）并加 1–2 px 的震动，强化「快打飞了」的感觉。
- 撞击瞬间沿撞击方向震动，震幅随撞击速度增加。现有工程的 `camera_shake.gd` 可以继续用。
- 同机多人对战时，镜头改为按所有角色外接矩形自动缩放，设上下限，避免一人出画。

| 页面 | 布局 | 要点 |
|---|---|---|
| 启动 / 标题 | 左侧竖排标题 + 竖排菜单，右侧角色立绘，背景钟楼内部 | 样张 2。立绘 = 正式序列帧中的大幅姿势，不需要额外绘制 |
| 鸦巢地图 | 竖向塔层图（自下而上），当前层高亮，Boss 层用暖红 | 爬塔主题天然适合竖向地图 |

## 七、与程序对接（Godot 实现要点）

1. **颜色统一从一处取。** 新建 `scripts/presentation/theme_palette.gd` 存上表所有十六进制值，UI、背景、特效、笔刷全部引用同一份，禁止各处硬编码。
2. **角色亮边用 shader。** 2D 精灵加一层外扩张描边（`canvas_item` 着色器，采样 alpha 后向外偏移 2 px 取最大），颜色 `#C9B6FF`。这一层在受击时改为暖红。
3. **UI 用 Godot Control 节点 + 九宫格（NinePatchRect），全部锚定贴边**，不要用绝对坐标堆在一起，否则换分辨率就崩。
4. **分辨率策略**：项目当前是 1280×720 viewport + `canvas_items` 拉伸。建议改成 1920×1080 设计分辨率 + `canvas_items` 拉伸（游戏内元素等比缩放），字体用动态字体以保持清晰。
5. **背景分层用 ParallaxBackground / Parallax2D**，系数按上表。
6. **特效层与角色层分离**：`CanvasLayer` 或 z_index 分层，保证特效不会盖住角色 UI。
7. **HUD 可配置**：把 `showComboCounter`、`showDamageNumbers` 等开关扩展成完整的 HUD 显示项，与设置页对应。

- [ ] 三种危险区在任何场景中都带暖色自发光。

## 十、我主动做的取舍（汇总，均可否决）

1. **不追求「画面漂亮」，追求「一眼看懂」。** 这套配色比纯夜景更亮、更对比，牺牲了氛围的柔和。理由：这是动作游戏，可读性优先。
2. **连击数字退出中央。** 牺牲视觉冲击，换取不遮挡。
3. **血条做细、裂羽值做大。** 用 UI 引导玩家注意核心玩法。
4. **紫是玩家专属色。** 背景和敌人都不能碰紫，构图自由度换辨识度。
5. **战斗 HUD 不加装饰。** 装饰只留给菜单和结算。
6. **背景全部低饱和。** 背景美但不出彩，把出彩让给角色和机关。
7. **空战需要更多天空。** 站立层只占下方三成，镜头抬高；这会牺牲一点「地面战的厚重感」。
8. **暂不设计角色以外的立绘。** 立绘直接复用序列帧中的大幅姿势，省下美术预算给背景和特效。
