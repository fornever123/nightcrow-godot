# 角色显示尺寸：实测与结论

## 零、更正（2026-10-15）：380 px 偏大，改为 260 px 左右

380 px 是在空白背景上测出来的，只考虑了「角色看不看得清」，没有考虑**角色和场景物体的比例**。放进真实场景（浮岛图）以后，380 px 的角色比远处的石拱还大，画面显得不协调。

在浮岛场景上按 200 / 240 / 280 / 320 / 380 px 对比（`art/gpt-size-compare.png`），并对照参考视频：

| 高度 | 占屏高 | 观感 |
|---|---|---|
| 参考视频 | 约 15%（≈160 px） | 场景感最强，但角色细节看不清，适合探索游戏 |
| 200 px | 19% | 协调，场景宏大；动作细节偏小 |
| 240 px | 22% | 协调，动作开始清楚 |
| **260–280 px** | 24–26% | **推荐：和场景协调，动作和刀光也看得清，适合动作游戏** |
| 320 px | 30% | 偏大，开始压场景 |
| 380 px | 35% | 太大，不协调 |

**新建议：默认 260 px，可在 240–280 px 之间调。** 尺寸仍然做成可配置参数。
380 px 时 3 px 像素块合适；降到 260 px 后，像素块建议改为 2 px，否则脸部细节会丢，进游戏实测后定。

## 一、实测数据

### 1. 源图原生裁剪尺寸（去掉 3200×3200 画布空白后）

| 动作 | 裁剪后尺寸 |
|---|---|
| 空中下坠 | 1174 × **977** |
| 空中普攻一段 | 1630 × **1019** |
| 空中普攻三段 | 1923 × **1146** |

**也就是说，角色的真实细节约在 1000 px 高。** 之前按 220 px 使用，只用掉了不到四分之一的可用分辨率。

### 2. 放大质量检验（`size-face.png`）

自 220 px 放大到 560 px，逐档看头部特写：眼睛高光、发型层次、白挑染、紫色渐变都没有出现涂抹或模糊，560 px 时反而更干净。

**结论：在 560 px 以内，放大不会损失质量。**

### 3. 上限推算

源图约 1000 px 高。若要保证「屏幕上每个像素至少有 2 个源像素」（2 倍超采样，缩放时不产生锯齿和闪烁），屏幕显示高度上限约为：

```
1000 ÷ 2 ≈ 500 px
```

再考虑镜头会临时推近（撞击特写、PVP 镜头），留 15% 余量：

```
技术上限 ≈ 430 px
```

### 4. 战场同屏对比（`battle-size-compare.png`）

同一场景、同一角色帧，仅改显示高度：

| 高度 | 占屏高比例 | 观感 |
|---|---|---|
| 220 px | 20% | 太小，没有存在感，像网页小游戏 |
| 320 px | 30% | 像个正经游戏，能看清面部与护甲 |
| **420 px** | 39% | **最有精品动作游戏的分量，刀光与目标的距离关系一眼可读** |
| 520 px | 48% | 偏大，横向空间紧张，接近技术上限 |

## 二、结论与建议

**推荐 380–430 px（占屏高 35%–40%）。**

理由：
1. 落在放大质量的甜区（远低于 560 px 的无损上限），仍有 2 倍超采样余量。
2. 刀光、护甲、面部特征都可读——这正是「效果很棒」的前提。
3. 给镜头推近留了余量。

### 但最终尺寸取决于玩法内核（仍未定）

尺寸其实是玩法决定的，不是审美决定的：

| 同时在场敌人数量 | 建议尺寸 | 对应手感 |
|---|---|---|
| 1–2 个（对决型） | 420–460 px | 格斗游戏的分量，动作细节最清晰 |
| 3–5 个（清场型） | 300–380 px | 看得清自己，也看得清敌人 |
| 6 个以上（割草型） | 200–260 px | 强调空间与调度 |

**因此工程上要做的不是「定一个尺寸」，而是把尺寸做成一个可配置参数**，改一个数字就能整体缩放。这样内核定了以后调整成本接近零。

### 一项工程约束

**角色素材不要再重复缩放。** 导入时一次性从原生 1000 px 缩到「显示尺寸 × 2」，之后运行时只做整数或等比缩放。反复缩放会累积模糊。

## 二·补 刀光必须拆层（实测发现，比尺寸本身更重要）

### 发现

对刀光区域做放大检查（`art/edge-check.png`）后确认：**紫色刀光与白色高光的交界处有明显的阶梯状锯齿和块状纹理**，这是 AI 放大留下的痕迹。角色的粗描边本身没有问题。

原因是**处理需求互相冲突**：

| 内容 | 需要的缩放方式 | 原因 |
|---|---|---|
| 角色本体 | 锐利（Lanczos / 保持硬边） | 保住描边和面部细节 |
| 刀光 | 轻微模糊 | 柔和光效的锯齿要被抹掉，否则一眼看穿是低分辨率放大 |

两者烘焙在同一张图里，同一张图只能选一种处理方式，**必然牺牲一边**。放大到 400 px 以上时，这个矛盾就会暴露。

### 结论

**刀光必须从角色帧中拆出来，作为独立图层。**

拆开以后连带解决三个已有问题：
1. 缩放可以分别处理（角色锐利、刀光模糊）。
2. 命中停顿时可以让角色停顿而刀光继续衰减，比现在「整帧一起停」自然得多。
3. 刀光不再遮挡角色身体。
4. 刀光可以调亮度、颜色、叠加模式，不再被烘焙死。

### 三种拆法（按可靠性排序）

| 方法 | 做法 | 适用 |
|---|---|---|
| **重新生成** | 让 AI 按提示词生成「无特效版本」的角色动作帧 | **最推荐**。干净、可控，但要重跑动作生成 |
| 色域分离 | 刀光是特定紫色系，按色相 + 亮度阈值自动分离 | 现有素材可用，需人工逐帧检查边缘 |
| 手工描边 | 逐帧手绘 mask | 精确但慢，不适合几十帧 |

**建议**：现有这 44 帧先用「色域分离」处理（工程里已有 SAM2 / RVM / ViTMatte，可辅助）；**以后的新动作一律要求生成无特效版本**，特效单独生成或用程序绘制。这也是 `AI生图提示词.md` 里特效提示词要求纯黑底的原因——纯黑底的特效不用抠，直接叠加。

### 这条约束对美术方向的影响

刀光拆层后，特效从「烘焙死的紫色弧」变成「可独立设计的图层」，于是：
- 特效风格可以和背景风格分开设计，不必迁就角色的紫色。
- 撞击、命中、弹刀可以统一成一套特效语言（见视觉规范第四节）。
- 之前担心的「刀光锯齿在大尺寸下露馅」不再是问题——模糊处理即可。

## 三、尺寸变大以后，美术方向的判断要跟着改

这是本轮最重要的连带影响。我之前给美术方向的约束建立在「角色只有 220 px」这个错误前提上，必须修正：

| 项目 | 原来的判断（220 px） | 修正后（380–430 px） |
|---|---|---|
| 背景细节程度 | 必须大块面，细纹样会变噪点 | **可以承载中等细节**。角色只占画面 39%，背景仍是大面积，但可以有纹样、砖缝、雕饰 |
| 背景留白要求 | 中央必须极干净 | 仍然要干净，但不必是「空」；可以是低对比的平静区域 |
| 角色轮廓光 | 必需（否则太小的深色块看不清） | 仍然建议，但不再是为了「看见」，而是为了「突出」。内部细节现在自己会说话 |
| 机关与危险区 | 必须大而显眼 | 可以做得更精致，细节层可以增加 |
| 特效尺寸 | 要小、要克制 | **可以放大**。420 px 的角色周围有充足空间，撞击特效可以做得有冲击力 |
| T3 明暗极简方向 | 靠轮廓光救场，尚可 | **风险上升**。角色变大后，大面积近黑背景会显得「空」而不是「压抑」，且浪费了角色的细节表现力 |
| T2 厚涂电影方向 | 风格冲突明显 | 冲突依然存在，但角色的内部细节能撑起更多质感，兼容性略好 |
| T1 / T4 / T5 | 可用 | 依然可用，且细节预算更宽裕 |

### 一句话总结

**角色变大是净收益**：画面质量上限提高、特效有发挥空间、背景可以更精致。但代价是**背景美术的制作标准要一起提高**——原来「大色块就够」的做法在新尺寸下会显得廉价。这一点要写进生图要求里。
